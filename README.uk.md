# Umbra RGB Add-on

[English](README.md)

Неофіційний аддон із відкритим кодом для **AsiaHorse Umbra**, який дозволяє використовувати ручну кількість LED, коли автоматичне визначення пропускає ARGB-пристрій.

Аддон змінює **локальну копію встановленої програми**. Це не офіційний API плагінів Umbra, не оновлення прошивки й не повне переписування програми. Оригінальна програма написана на Python і запакована в EXE; цей проєкт додає невеликий Python-хук до її запуску.

## Що виправляє аддон

Пристрій може реагувати на вибір порту та перевірку кількості LED, але Umbra продовжує показувати **0 LED** і пропускає його в анімаціях. Прошивка перевіреного хаба вже підтримує збережену ручну кількість, проте активує її під час запуску хаба.

Аддон:

- Зберігає явно вибрану кількість LED для **фізичного ARGB-порту 1** в локальному профілі та штатній RGB-конфігурації хаба.
- Розрізняє збережену кількість і фактично активну кількість, яку повідомляє хаб.
- Вмикає керування RGB через USB перед звичайними ефектами та після перевірки кількості LED.
- Передає штатні дані ефектів без змін і використовує реальну топологію хаба для розподілу RGB.
- Не повторює команду встановлення кількості автоматично під час запуску чи виходу.

Аддон не підміняє виробника: JONSBO не потрібно видавати себе за JUMPEAK. Механізм потенційно підходить і для інших ARGB-пристроїв із невдалим автовизначенням, але інші поєднання фізично не перевірені.

## Підтримувана конфігурація

| Компонент | Поточні межі підтримки |
| --- | --- |
| ОС | Windows; окремий інсталятор для **x64** |
| Оригінальна програма | AsiaHorse Umbra **V3.5.5_09.03** |
| Оригінальний EXE | `Sync_light.exe`, точний SHA-256 нижче |
| Перевірений контролер | USB VID `1A86`, PID `FE04` |
| Досліджена та перевірена прошивка | **1.0.6** |
| Ручне налаштування | Фізичний ARGB-**порт 1**, значення **0–100** |
| Фізична перевірка | Власник підтвердив розпізнавання башти JONSBO та роботу підсвітки після перезавантаження ПК |

SHA-256 підтримуваного оригінального EXE:

```text
974f28ff684091520bb742cf4a24dabd726c483b08094ded871ab87f90ab5e25
```

Патчер відхиляє невідомий EXE. Однакового напису версії недостатньо. Інші порти, контролери, версії прошивки та оновлення програми не входять до перевіреної конфігурації.

Фізичне підтвердження стосується початкової приватної збірки сумісності. Перевірки публічного пакета описані окремо у [VERIFICATION.md](VERIFICATION.md); перевірка інсталятора сама по собі не підтверджує фізичну роботу RGB.

У робочому локальному варіанті перед перезавантаженням ПК було збережено **7**. Це результат для конкретного пристрою, а не універсальне значення чи рекомендація для кожної башти. Телеметрія фактично активної кількості після перезавантаження не збереглася. Публічний пакет **не встановлює 7 або 24 наперед**.

## Встановлення

Завантажте **[Umbra-RGB-Addon-Setup-0.2.0.exe](https://github.com/TarasDzia/umbra-rgb-addon/releases/download/v0.2.0/Umbra-RGB-Addon-Setup-0.2.0.exe)** зі [сторінки релізу 0.2.0](https://github.com/TarasDzia/umbra-rgb-addon/releases/tag/v0.2.0). **Встановлювати Python чи відкривати PowerShell не потрібно.** Потрібна ваша власна інсталяція підтримуваної Umbra з `Sync_light.exe` та всіма допоміжними файлами.

1. Закрийте Umbra та інші RGB-програми, що керують тим самим хабом.
2. Запустіть інсталятор і виберіть папку оригінальної Umbra, у якій міститься `Sync_light.exe`.
3. Виберіть **нову окрему папку призначення**. За замовчуванням це `%LOCALAPPDATA%\UmbraRGBAddon\v0.2.0`; якщо вона вже існує, інсталятор пропонує вільну назву.
4. Перевірте вибрану інсталяцію та почніть встановлення. Інсталятор приймає лише точний підтримуваний оригінальний EXE з повним середовищем виконання.
5. Після завершення самостійно запустіть `Umbra-RGB-Addon.exe` зі створеної папки. Усі допоміжні файли мають залишатися поруч.

Інсталятор містить власне середовище Python/Tk для вікна та патчера. Він копіює середовище Umbra з вашої локальної інсталяції й додає код цього проєкту. Створена програма зберігає комплектний Python 3.8 виробника.

Під час встановлення інсталятор не запускає Umbra, не відкриває хаб, не надсилає HID-пакети, не встановлює драйвери та нічого не завантажує з мережі. Він не перезаписує наявні папки; оригінальна інсталяція та файли SignalRGB залишаються без змін. Інсталятор і змінений локальний EXE не мають цифрового підпису: підпис оригіналу не переноситься на змінену копію.

Якщо копіювання чи патчинг завершиться помилкою, інсталятор покаже її та залишить частково створену папку для перевірки. Повторіть встановлення в нову папку; неповну копію можна видалити вручну, коли вона більше не потрібна.

## Налаштування кількості LED

1. У створеній копії відкрийте **Ctrl Settings** і виберіть **фізичний порт 1**.
2. Явно виберіть відповідну **LED Count** для підключеного пристрою. До вашого вибору ручне значення в хаб не записується.
3. Перезавантажте ПК, знову відкрийте `Umbra-RGB-Addon.exe` та перевірте звичайний ефект підсвітки.

У прошивці 1.0.6 це **резервне ручне значення**: під час запуску хаб застосовує
додатну збережену кількість лише тоді, коли вона більша за автоматично визначену.
Так можна відновити порт, визначений як нуль, але не примусово зменшити успішно
визначену кількість. Значення 0 вимикає ручний обхід при наступному запуску хаба;
це не універсальний перемикач вимкнення підсвітки.

Самого перезапуску програми недостатньо для активації збереженого значення на перевіреній прошивці. Роботу підтверджено після перезавантаження ПК; аддон не надсилає команду скидання контролера. Якщо під час перезавантаження хаб увесь час залишається під живленням, для його нового запуску може знадобитися повне вимкнення та повторне ввімкнення живлення.

Шаблон **N−1 червоних елементів і один білий** одразу після зміни кількості — штатна перевірка прошивки. Це не анімація й не доказ того, що робоча топологія для ефектів уже змінилася. Статус збереженої та активної кількості допомагає відрізнити ці стани.

## Лише RGB

Транспортний фільтр дозволяє лише підтримувані форми RGB-пакетів. Він блокує PWM вентиляторів, команди скидання контролера (`FA`, `07`, `FC`), налаштування запуску (`0B`, `0C`), feature-записи та запис прошивки. У створеній копії вимкнено інсталятори драйверів і допоміжні процедури підвищення прав та автозапуску.

**Керування швидкістю вентиляторів в інтерфейсі копії через цей аддон не працює.** Проєкт змінює лише поведінку підсвітки й не змінює та не встановлює прошивку хаба.

Одночасно використовуйте одну програму керування RGB. Пакет не встановлює й не змінює плагіни SignalRGB.

## Оновлення та видалення

- **Оновлення аддона:** закрийте створену копію та встановіть нову в іншу папку з тієї самої підтримуваної оригінальної інсталяції. За потреби окремо збережіть профіль: нова папка не обов'язково успадковує профіль старої.
- **Оновлення Umbra:** невідомий EXE відхиляється. Дочекайтеся підтримки конкретної збірки, не обходьте перевірку хешу.
- **Видалення:** закрийте копію з аддоном і видаліть тільки створену для неї папку. Оригінальна Umbra залишиться доступною.

Видалення папки **не скасовує** ручну кількість LED, уже збережену в хабі. Встановлення та видалення не надсилають апаратних команд. Фонової служби, мережевих завантажень та автоматичного оновлення немає.

## Якщо щось не працює

| Симптом | Що перевірити |
| --- | --- |
| Патчер відхиляє `Sync_light.exe` | Потрібен підтримуваний оригінальний EXE: інші збірки та вже змінені копії мають інший хеш. |
| Не знайдено файли середовища | Виберіть повну папку встановленої Umbra, а не окремо скопійований EXE. |
| Папку призначення відхилено | Виберіть нову папку поза оригінальною інсталяцією та вихідним кодом аддона. Лише для CLI батьківська папка має вже існувати. |
| Встановлення зупинилося під час копіювання | Збережіть текст помилки, за потреби перегляньте неповну копію та повторіть встановлення в нову папку. |
| Перевірка кількості світиться, а ефекти ні | Після явного вибору кількості перезапустіть ПК/хаб; порівняйте збережену та фактично активну кількість. |
| Колір змінює інший порт | Реліз підтримує фізичний порт 1; список компонентів іншої RGB-програми не встановлює фізичний номер порту. |
| Кнопки швидкості вентилятора не діють | Це очікувано: PWM заблоковано в RGB-копії. |

Для повідомлення про проблему вкажіть версію та хеш оригінальної програми, VID/PID і прошивку контролера, фізичний порт, вибрану кількість, активну кількість за наявності та результат перезавантаження ПК. Не завантажуйте створену програму, всю папку середовища або непереглянуті особисті журнали й профілі.

## Для розробників

### Встановлення з вихідного коду

Патчер командного рядка залишається доступним і використовує лише стандартну бібліотеку Python. Для нього потрібен **Python 3.8 або новіший**; саме версію 3.8 встановлювати не обов'язково. Завантажте й розпакуйте вихідний пакет, закрийте RGB-програми та виконайте:

```powershell
python patcher.py inspect --source "C:\path\AsiaHorse UMBRA"
python patcher.py install --source "C:\path\AsiaHorse UMBRA" --destination "C:\path\Umbra-RGB-Addon"
```

Папка призначення має бути новою та розташованою поза оригінальною інсталяцією й вихідним кодом аддона. Для CLI її батьківська папка має вже існувати. Після встановлення запустіть створену програму самостійно.

### Тести та збирання

Запуск офлайн-тестів із папки проєкту:

```powershell
python -m unittest discover -s tests -v
```

Версія 0.1.0 пройшла 50 офлайн-тестів на Python 3.8 і 3.14. Окремо перевірено запуск створеної копії без доступу до USB. Перевірки поточного релізу та їхні межі наведено у [VERIFICATION.md](VERIFICATION.md).

Вихідний пакет містить наш хук, патчер, інсталятор, тести, документацію, читабельний вихідний код bootstrap, інструменти збирання та попередньо скомпільований **власний bootstrap для Python 3.8**, збережений як текст base64. Він дозволяє новішому Python підготувати програму з комплектним Python 3.8 без виконання її коду під час встановлення. Для перекомпіляції bootstrap потрібен Python 3.8; для звичайного встановлення — ні.

Збирання окремого інсталятора у Windows із **Python 3.14 x64** в окремому середовищі. Батьківська папка для вихідного EXE має вже існувати:

```powershell
python -m pip install -r requirements-build.txt
python tools/build_windows_installer.py --output "C:\path\Umbra-RGB-Addon-Setup-0.2.0.exe"
```

У вимогах зафіксовано PyInstaller **6.22.3**. Інсталятор містить власний інтерпретатор і бібліотеки Tk, тому користувачу Python не потрібен. Його іконка Umbra — окремо атрибутований ресурс бренду, описаний нижче. Оригінального чи зміненого EXE Umbra, бібліотек виробника, витягнутого коду або прошивки в інсталяторі немає.

Перекомпіляція bootstrap Python 3.8 та створення вихідного архіву:

```powershell
py -3.8 tools/build_bootstrap38.py
python tools/build_source_release.py
```

Друга команда створює вихідний ZIP поруч із папкою проєкту: з явним списком файлів, маніфестом їхніх хешів і контрольною сумою архіву. Папки зі створеним середовищем виробника не скануються для включення до архіву.

Під час змін зберігайте перевірку конкретної версії, фільтр пакетів, окрему папку призначення, записи кількості лише за явною дією, розподіл RGB за реальною топологією та розділення збереженого й активного стану. Тести не повинні вимагати підключеного контролера.

Перевірка запуску створеної копії без USB:

```powershell
$env:UMBRA_RGB_DRY_RUN = "1"
& "C:\path\Umbra-RGB-Addon\Umbra-RGB-Addon.exe"
Remove-Item Env:\UMBRA_RGB_DRY_RUN
```

Цей режим пропускає реальне перерахування HID-пристроїв. Офлайн-тест чи успішний запуск програми не підтверджує фізичну роботу з іншим пристроєм або контролером.
